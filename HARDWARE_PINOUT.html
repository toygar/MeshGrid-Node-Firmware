MeshGrid Node — Hardware list and pinout

This document is published only in the MeshGrid-Node-Firmware repository. Hardware pinout and wiring summary are provided here as the official reference. Full source tree, provision.py, partitions.csv, and build instructions are not published in this repo (kept in a separate / internal project).

Connection diagram (reference): ESP32, E22 LoRa, GPS, and battery with a 10k+10k voltage divider — see HARDWARE_SCHEMATIC.svg (open in a browser; printable). No PCB; breadboard / wiring aid only.

The firmware assumes the following hardware; your actual board may use different solder joints or connectors.

ComponentRoleNote
ESP32 development module Main MCU, BLE, WiFi (BLE used for mesh companion link), USB-serial PlatformIO: esp32dev. Onboard LED is usually GPIO2.
Ebyte E22 (or compatible) LoRa module Mesh RF, UART AT/transparent Firmware: 9600 8N1. AUX indicates module idle for UART.
u-blox NEO-7M (or NMEA-compatible GPS) Position (NMEA) Default 9600 baud. GPS TX→ESP32 RX, GPS RX←ESP32 TX.

5. Battery (18650) — two 10k resistors to GPIO34

Cell voltage can reach 4.2 V; ESP32 ADC input must not exceed ~3.3 V. Equal divider (10k+10k): VGPIO34 = Vbat / 2. Firmware computes Vbat = Vpin × 2.

18650 (+) ----[ R1 10k ]----+---- GPIO34 (ADC1_CH6, input only)
                             |
                             +----[ R2 10k ]---- GND (common with cell (-) and ESP32 GND)
18650 (-) ------------------------ GND

Battery (-) and ESP32 GND must share the same reference (common ground).
When powered only from USB: no cell → ADC may read noise or 0 V — expected.

Safety: Wiring 4.2 V directly to a GPIO will damage the ESP32. Verify the divider (e.g. ~2.1 V on GPIO34 at full charge).

BLE telemetry (firmware): MESH_TYPE_STATUS, event = 0x43 (MESH_STATUS_EVENT_NODE_BATTERY), detail = 0–100%, auxValue = cell mV. Parse this packet in the mobile app.
